# 项目规则（langlang）

本项目为 LangChain / LangGraph **学习仓库**，以下规则为项目级管理约束，任何开发、同步本仓库的工作都必须遵守：

1. **学习优先，克制扩展**：项目主要用于学习。在提供伪代码 / 需求的情况下，不盲目扩展花哨功能，严格贴合教学进度，让阅读者"学明白、看明白"，而非堆砌炫技操作。

2. **模型固定 deepseek-v4-flash**：本项目大模型始终固定为 `deepseek-v4-flash`。密钥保存在 `.env`（不入库），通过 `langchain-deepseek` 的 `DEEPSEEK_API_KEY` 读取；模型名直接写在各章节 agent 脚本中。

3. **严禁硬编码密钥**：项目会同步 GitHub。任何测试与提交过程中，工程文件内严禁出现硬编码的 api-key / 密钥 / 专属 Host 等私密信息。全部密钥只存 `.env`（已被 `.gitignore` 忽略）。

4. **真实工程化，不用模拟数据**：用伪代码构建工程时，尽可能用标准工程化方法实现真实功能（真实 API 调用、安全实现，如用 `ast` 白名单替代裸 `eval`），而非以硬编码假数据 / 危险简化敷衍演示，以提升学习真实性。

5. **学习日志**：在 `examples/` 下维护 `学习日志.md`，按章节（test_01 / test_02 / …）记录主要学习内容、关键认知与踩坑，随教学进度持续追加。

6. **案例驱动学习（学了方法就要落到真实问题）**：每章节学到一个知识点后，必须主动思考"这个方法能解决现实生活中的哪些具体问题"，并结合**一个真实业务场景**去生成工程，而非只写"演示这个 API 长什么样"的孤立脚本。工程内要同时讲清三件事：(a) 场景是什么、痛点是什么；(b) 用到了哪个方法、为什么它能解这个问题；(c) 这个方法的边界/局限性（如某 provider 不支持某特性）。让学习者在理解 API 之外，还能建立"知识 → 问题 → 方案 → 边界"的完整心智。

## 技术约定

- 依赖管理：`uv` + `pyproject.toml` + `uv.lock`（锁文件在容器内针对 Python 3.11 生成）。
- 环境：`Dockerfile` 镜像 `langchain-lab:3.11`；运行脚本 `dev.ps1` / `rebuild.ps1`。
- 密钥：和风天气强制使用账号专属 API Host，Host 与 Key 同属敏感认证信息，均只存 `.env`。
